## 1. Overview

This document provides an overview of how I implemented my web app Architician, the tools I used for building the app, and my reasons for choosing those tools

## 2. Frontend

The front end is implemented using React with javaScript and a good number of Mantine Library components like papers, inputs and buttons. I decided to incorporate Mantine components because they provide great abstraction, enabling the use of fewer lines of code for my application. I choosed React for a similar reason. The creation and reuse of components allows for greater abstraction and code reuse making it easier acheive more using fewer lines of code.

The frontend is a combination of a variety of components ( Home.js, card.js, scoreCard.js etc.), two useContexts for the Auth and checkedAuth variables (So that that other components like the log in can also access and update the user's authentication state).

Originally, I planned to use shadcn for components. However, I found it easier to use Mantine than shadcn because the app is written in javaScript and not typeScript. I found the Mantine components easier to integrate into React with javaScript that the shadcn components. I used several Mantine components including the card, buttons, papers and input fields.

The navbar logo was generated by vistaPrint

## 3. Backend and Data Management

The backend service is implemented using Flask with Python. I choose Flask for creating the API endpoints because I already had some knowledge on using flask from CS50's lectures and problem sets. I used the standard HTTP verbs (GET, POST, DELETE) and status codes (400, 401, 409 etc.). Data is stored using a sqlite3 relational database archistician.db. I decided to use a relational database over no database so that user data doesn't just disappear upon refresh of the app, as the app is meant to keep and track the user's growth. Also, using the database enforces data integrity by applying integrity constraints.

There are four tables habits, ideas, scores and users. The tables habits and ideas have API endpoints for getting all data, posting new data, and deleting a row. The table scores has API endpoints for getting the past n scores, and posting a new score. I used the ON CONFLICT keyword to ensure that the score for a day is overwritten if the user submits the habit scorecard again. The table users has endpoints for posting a new user (sign up) and getting a specific user's username and id (but not their password hash). For hashing passwords, I decided to use  werkzeug.security because we had already used it in CS50 for the finance Pset.

app.py also has endpoints for logging a user in, logging them out, and getting the user's authentication status (/session). The user sessions are implemented using flask session.
